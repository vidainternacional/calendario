# FASE H — BLOQUE 2 — CHECKLIST MÓVIL DE VALIDACIÓN

Fecha de preparación: 2026-08-19
Estado: **PREPARADO — ejecutar únicamente sobre un Preview cuyo commit coincida con el head validado de la rama**.

Este checklist existe para que la validación final del Bloque 2 sea principalmente una revisión funcional/visual en iPhone y no una nueva ronda de desarrollo.

## Antes de empezar

- [ ] Confirmar que el Preview pertenece a `agent/fase-h-hebreo-biblico` y que el commit mostrado por Vercel coincide con el head que tenga CI verde.
- [ ] Entrar con una cuenta VIDA normal y abrir `Estudios → Hebreo Bíblico`.
- [ ] No hacer merge ni producción durante esta validación.

## 1. Inicio y contrato visual

- [ ] Los cuatro accesos principales siguen visibles: Aprender, Materiales y curso, Prueba tu progreso y Biblia en hebreo.
- [ ] Los textos pedagógicos, explicaciones y ayudas aparecen centrados; no quedan párrafos explicativos pegados a la izquierda.
- [ ] Buscadores y campos de escritura conservan alineación funcional para escribir hebreo/usar el cursor.
- [ ] No aparecen tarjetas anidadas innecesarias ni doble borde/ring.
- [ ] La tipografía hebrea conserva espacio suficiente para niqqud y no corta puntos o trazos.
- [ ] La navegación inferior global no se levanta ni flota de forma incorrecta al abrir el teclado del teléfono.

## 2. Teclado hebreo VIDA

- [ ] Al entrar, el teclado VIDA está apagado por defecto y no hay botón flotante innecesario.
- [ ] La herramienta superior permite Activar / Desactivar el teclado.
- [ ] Al activarlo aparece el acceso flotante suficientemente arriba de la navegación inferior.
- [ ] Letras muestra las 22 letras y las 5 formas finales.
- [ ] Vocales/Niqqud permite insertar signos sobre el texto de práctica o el último campo enfocado.
- [ ] El teclado VIDA escribe en un buscador de Palabras después de tocar primero ese buscador.
- [ ] `↵` puede ejecutar la búsqueda cuando corresponde.
- [ ] La práctica libre no altera el buscador ni pretende guardarse como progreso.
- [ ] El teclado hebreo nativo del iPhone sigue pudiéndose usar normalmente.

## 3. Alef-Bet — fundamentos del Bloque 2

- [ ] Tarjetas, Lista y Detalle siguen funcionando como antes.
- [ ] Las 22 letras básicas siguen presentes y Shin/Sin no se duplicaron como dos letras del alfabeto.
- [ ] La tabla Sofit muestra כ→ך, מ→ם, נ→ן, פ→ף y צ→ץ.
- [ ] Los valores ordinarios permanecen separados de 500–900, que debe aparecer únicamente como convención ampliada de gematría.
- [ ] Dagesh/Begadkefat compara ב/בּ, ג/גּ, ד/דּ, כ/כּ, פ/פּ y ת/תּ.
- [ ] La explicación de Begadkefat no afirma que todas las tradiciones modernas conserven exactamente los mismos contrastes históricos.
- [ ] Matres lectionis presenta א, ה, ו, י como letras que en ciertos contextos ayudan a indicar vocales, no como vocales independientes universales.
- [ ] Las tablas pueden desplazarse horizontalmente si hace falta sin encoger el hebreo hasta volverlo incómodo.

## 4. Vocales / Niqqud avanzado

- [ ] Básicas sigue mostrando 8 vocales completas; Reducidas 3; Sheva 1; Todas 12.
- [ ] Lista sigue mostrando el signo aplicado a una consonante y no solo un símbolo abstracto.
- [ ] `Sheva` permite comparar función vocal y silenciosa.
- [ ] En בְּרֵאשִׁית se explica la práctica inicial de sheva vocal.
- [ ] En מַלְכָּה el sheva bajo ל se presenta como silencioso en la lectura orientativa mal-ká.
- [ ] `Qamats` distingue qamats común de qamats qatan.
- [ ] כָּל se lee de forma orientativa como `kol` y no se fuerza la regla “todo qamats = a”.
- [ ] `Pataj furtivo` muestra רוּחַ y explica que la `a` se oye antes de la consonante gutural final.
- [ ] `Sílabas` progresa consonante → consonante+niqqud → sílaba → מֶלֶךְ → מלך.
- [ ] Ninguna explicación convierte las reglas iniciales de sheva/silabificación en fórmulas universales.

## 5. Palabras y Lectura — no regresión rápida

- [ ] Palabras conserva Tarjetas · Lista · Detalle, categorías, paginación y Con niqqud / Sin niqqud.
- [ ] Buscar una palabra hebrea funciona también al escribirla sin niqqud.
- [ ] Buscar en español devuelve candidatos sin presentar una coincidencia contextual de RV1909 como equivalencia léxica uno-a-uno cuando no hay glosa aprobada.
- [ ] Lectura conserva frases/versículos reales, paginación, niqqud y comparación RV1909.
- [ ] El tamaño del hebreo sigue siendo cómodo en móvil y no se degrada por las nuevas tablas de gramática.

## 6. Reglas — gramática nominal

- [ ] Reglas abre en Tablas y conserva Fichas y Detalle.
- [ ] En Fichas/Detalle aparecen los filtros Básicas · Prefijos · Nombres · Verbos · Frase · Todas.
- [ ] Prefijos conserva artículo, conjunción y preposiciones inseparables con cautelas contextuales.
- [ ] Género/número presenta terminaciones como pistas y no como reglas absolutas.
- [ ] `Sufijos posesivos` muestra persona y sufijos frecuentes.
- [ ] `Base → sufijo → palabra real` contiene ejemplos como בֵּן + ־ִי → בְּנִי y פֶּה + ־וֹ → פִּיו.
- [ ] La explicación deja claro que la base puede cambiar al recibir el sufijo.
- [ ] `Estado constructo` compara formas reales como בֵּן/בֶּן/בְּנֵי y דָּבָר/דְּבַר/דִּבְרֵי.
- [ ] La cadena בֵּית הַמֶּלֶךְ se entiende como una unidad y no se enseña a colocar artículo directamente en el primer nombre constructo.
- [ ] No aparece ninguna raíz deducida visualmente como si fuera dato de la fuente.

## 7. Reglas — primer mapa verbal Qal

- [ ] El filtro `Verbos` existe y no mezcla accidentalmente las fichas de Prefijos/Nombres.
- [ ] La primera explicación diferencia lema y forma flexionada usando אָמַר.
- [ ] Aparece la comparación qatal `אָמַר` ↔ yiqtol `יֹאמַר`.
- [ ] Qatal explica que las marcas personales aparecen principalmente como terminaciones.
- [ ] Yiqtol explica que las marcas aparecen sobre todo como prefijos y, en varias personas, también como terminaciones.
- [ ] La tabla qatal permite comparar אָמַר, אָמְרָה, אָמַרְתָּ, אָמַרְתְּ, אָמַרְתִּי, אָמְרוּ, אֲמַרְתֶּם y אָמַרְנוּ.
- [ ] La tabla yiqtol permite comparar יֹאמַר, תֹּאמַר/תֹאמַר, תֹאמְרִי, אֹמַר, נֹאמַר, יֹאמְרוּ y תֹאמְרוּ.
- [ ] Imperativo `אֱמֹר` se reconoce como segunda persona masculina singular.
- [ ] Participio `אֹמֵר` no se presenta siempre como gerundio español.
- [ ] `לֵאמֹר` se explica como לְ + infinitivo constructo de אָמַר.
- [ ] `וַיֹּאמֶר` se presenta como wayyiqtol frecuente en narración.
- [ ] `וְאָמַרְתָּ` se presenta como weqatal dentro de una secuencia discursiva.
- [ ] En ningún lugar la app dice simplemente `qatal = pasado`.
- [ ] En ningún lugar la app dice simplemente `yiqtol = futuro`.
- [ ] En ningún lugar la app enseña `wayyiqtol = ו + futuro convertido en pasado`.

## 8. Repaso — integración del Bloque 2

- [ ] Repaso conserva Mixto · Letras · Vocales · Palabras · Lectura · Reglas y ahora incluye `Verbos`.
- [ ] Mixto sigue siendo una sesión de hasta 8 elementos y contiene al menos una práctica verbal además de las áreas anteriores.
- [ ] Vocales incluye prácticas específicas de sheva vocal, sheva silencioso, qamats qatan y pataj furtivo.
- [ ] Reglas incluye prácticas de בְּנִי, אָבִיו, constructo de דָּבָר y בְּנֵי.
- [ ] Verbos contiene 8 prácticas: qatal/yiqtol, qatal 1cs, yiqtol 1cs, imperativo, participio, infinitivo constructo, wayyiqtol y weqatal.
- [ ] Mostrar respuesta funciona en todas esas prácticas.
- [ ] Lo sé · Necesito practicar · Repasar después avanzan correctamente al siguiente elemento.
- [ ] Al terminar aparece el resumen de la sesión.
- [ ] El resumen sigue diciendo que no se guarda como progreso.
- [ ] Cambiar de categoría/reiniciar no deja respuestas o escritura de la sesión anterior pegadas en pantalla.

## 9. Comportamiento global de móvil

- [ ] No hay textos pedagógicos inesperadamente alineados a la izquierda.
- [ ] No hay contenido hebreo cortado por altura de línea.
- [ ] Los botones mantienen áreas táctiles cómodas.
- [ ] Las tablas anchas hacen scroll horizontal sin mover toda la página lateralmente.
- [ ] Abrir/cerrar disclosures no produce saltos visuales extraños.
- [ ] El scroll vertical sigue siendo natural en iOS.
- [ ] No hay botones falsos de audio.
- [ ] No aparece ninguna promesa de progreso persistente que todavía no exista.
- [ ] No hay errores visibles al volver desde una sección a otra de Aprender.

## 10. Resultado de la validación

Marcar una de estas tres opciones para cada hallazgo:

- **OK** — comportamiento correcto.
- **VISUAL** — funciona, pero requiere ajuste de presentación.
- **BUG** — comportamiento reproducible incorrecto.

Para cualquier problema, registrar únicamente:

1. sección;
2. acción exacta realizada;
3. qué se esperaba;
4. qué ocurrió;
5. captura si el problema es visual.

No reabrir áreas aprobadas que no presenten un bug reproducible.
